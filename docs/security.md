# Single-Invitation Hardening

Phase 7 scope: the approved single-invitation workflow. Bulk UI remains disabled;
existing bulk work is retained. No Git setup, cloud deployment, authentication,
database, recipient storage, or typography changes are included.

## Policy

- Both single POST endpoints accept at most 16 KiB, measured before parsing.
- Request body reading has a total 10-second deadline.
- Preview and PDF generation share 30 attempts per client per 60 seconds.
- The rate tracker keeps at most 1,024 client buckets, each with at most 30 timestamps.
- One heavy request is admitted per worker; others receive 503 without body parsing.
- 429 and busy 503 responses contain `Retry-After`; all protected responses are no-store.
- Safe errors omit submitted values, unknown field names, internal paths, and tracebacks.
- Generated bytes remain in memory. Existing filename and fixed 16 pt layout rules remain.
- Browser security headers preserve same-origin form assets and blob-based exact previews.

The retained bulk POST endpoints share rate and admission controls, so they cannot bypass
the shared PDF renderer's bounds. Their existing multipart allowance remains unchanged.
See [the API contract](single-api.md) for status codes and deployment limitations.
